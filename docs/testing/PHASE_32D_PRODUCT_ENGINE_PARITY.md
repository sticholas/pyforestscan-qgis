# Phase 32D Product Engine Parity

The managed launch contract applies uniformly to CHM, Rumple, PAI, PAD, FHD, Canopy Cover, DTM, Point Density, and Voxel Statistic. Polygon execution binds one Prerun token to the adapter, and each product job receives that token. No routed product may select QGIS Python or call fresh backend readiness discovery after token freeze.

Automated parity coverage iterates the complete `PBM_ROUTED_PRODUCTS` registry and asserts every product reaches `run_product(..., runtime_token=frozen_token, runtime_products=prerun_products)`.

The packaged QGIS 3.44.13 test froze one token for PAI and FHD, completed Repair/Reload to `READY`, and observed both managed worker processes write execution-runtime traces with the same runtime generation. The harness then terminated only those owned workers before scientific processing, so this is launch-contract evidence rather than a product-output test.
