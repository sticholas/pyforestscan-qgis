# Dense View Pipeline Profile

Measured development work from Phase 34A3.2, continued in 34A3.3. Windows QGIS
3.44.13 / Qt5 and QGIS 4.0.0 / Qt6; one RTX 4090 workstation. Historical matrix
rows predate final cache-policy hardening and are not fresh-package certification.

## Former source limit

At baseline d8eb705, viewer/prepare_source.py rejected num_points above
MAX_UNINDEXED_POINTS = 2,000,000 before running readers.las -> writers.copc with
Pipeline.execute(). It guarded an in-memory conversion, not a renderer or LAS
format limit. The Qt ViewerWorker consumed compact preparation stdout and handed
the resulting file to the isolated renderer. The selection resolver contained
a second two-million-point check, subsequently exposed by raw Olaa editing QA.

Both user-facing ceilings are removed through bounded paths, not raised. Small
eligible LAS/LAZ uses a virtual single-node EPT descriptor serving the original
binary. Larger raw files use a managed out-of-core Untwine child and reusable
COPC. Raw authoritative selection remains a chunked original-source scan.

## Data and copy path

| Stage | Representation / ownership | Evidence and limit |
| --- | --- | --- |
| Original read | Binary file or requested EPT node / COPC range | No repository-wide EPT download |
| Loopback source service | Binary HTTP response; compact metadata JSON only | COPC ranges bounded at 32 MiB |
| Browser fetch | ArrayBuffer | Network/browser copies not directly measured |
| LAZ decompression | Worker-local WASM input and output allocations | Full-file wrapper frees both buffers on success/failure |
| Decode | Typed attribute buffers | Native COPC chunk decoder already frees its WASM buffers |
| Worker handoff | Transferable buffers | No million-point JSON serialization or QGIS point arrays |
| GPU upload | Resident node attributes | Existing incremental node admission; two GPU nodes per frame |
| Edit resolution | Original-source 65,536-record chunks | Cache LOD/order is not membership authority |

This is a source/code ownership audit, not an exact physical-copy count or
per-stage profiler. Read/decode/upload latency isolation remains incomplete.
The repaired vendor full-file decoder path previously omitted explicit WASM
input/point-buffer frees. The pinned vendor asset is not edited; an owned wrapper
provides lifecycle cleanup and has a Node failure/success allocation regression.

## Strategy qualification

The direct planner presently admits at most 100k points, 16 MiB encoded input
and 64 MiB estimated decoded cost, constrained further by available RAM and
advisory profile. Twenty thousand points passed direct LAS/LAZ tests. These
thresholds are conservative provisional admission limits, not an empirically
optimal boundary; 500k and above select an indexed cache. DIRECT_STREAMED is not
implemented. Native COPC and EPT do not create another full derivative.

Early preview/hot-swap was not enabled: it would create another source/view
handoff while identity, selection and cache lifecycle are still being qualified.
Predictive prefetch and a persistent EPT disk cache are not implemented. Existing
projected-node priority, parent-safe retention and bounded concurrency remain;
1/2/4/8 concurrency comparison and distinct learned network profiles are pending.

The first-frame improvement is about 13.7x in this pair. This was a shared-machine
development measurement, not a controlled cold-disk benchmark. The policy was
subsequently versioned to reject older flag-unsafe caches. The same raw LAZ uses
legacy point format; the channel workaround does not apply to that format.

The original 104.8M raw LAS also automatically indexed in the prior matrix; a
warm reopen on its network drive took 35.8 s of preparation, dominated by full
source fingerprinting. Source hashes are not skipped to manufacture warm timings.

## Cache integrity discovery

Full-record comparison of all 2,287,408 original records found matching XYZ,
classification, intensity, RGB, returns, GPS time, point source, HAG and CRS, but
incorrect ScanChannel and ScanDirectionFlag in Untwine 1.5.1 output.

The official [Untwine 1.5.1 bit map](https://github.com/hobuinc/untwine/blob/1.5.1/untwine/Common.hpp)
places scanner channel at bit five, overlapping scan direction. A temporary
streamed input supplies its channel bits through ClassFlags at bit four and
zeros only the temporary ScanChannel. The output standard fields then match.
The converter is pinned and this policy has its own cache identity.

The repeated all-record, all-original-dimension comparison passed, including
ScanChannel, ScanDirectionFlag and HeightAboveGround. Source hash stayed
0c688c22d42b0240c6cba19973087ee59606721289872a3f8237253548db34bb.
The corrected 2.287M preparation took 6.375 s; verified reuse took 0.703 s.
This verifies the tested point-format fixture, not all waveform/Extra Bytes cases.

## Export memory attribution

The original 104.8M LAS selection matched independent PDAL: 20,405 points.
Full export and all-dimension validation passed in 407.75 s including source,
selection and memory-instrumentation work. Peak process private bytes were
199,651,328; peak working set was 6,178,758,656 bytes.

One non-atomic validation-stage snapshot reported 5,975,527,424 resident mapped
bytes, 139,968,512 private resident bytes and 41,611,264 image resident bytes.
Python tracemalloc reported 42,497,778 current / 46,683,703 peak bytes in that
snapshot. Disk-backed point staging was 5,974,713,666 bytes.

Thus the roughly 6 GB working set is predominantly mapped-file residency, not
a 6 GB Python heap. It still consumes physical memory. Native allocations cannot
be attributed specifically to PDAL merely by subtracting tracemalloc; system
filesystem-cache ownership was not measured. The read-only Windows sampler uses
[VirtualQueryEx](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-virtualqueryex)
and [QueryWorkingSetEx](https://learn.microsoft.com/en-us/windows/win32/api/psapi/nf-psapi-queryworkingsetex).
Each deep sample took about 15 s and perturbed timing; no exporter rewrite was
justified by working set alone.

## Scope and release gate

Raw intake matrix: 20k, 500k, 2.287M, 5M, 10M, 50M and 104.8M. The intermediate
sizes are streamed Olaa subsets, not independent terrestrial/mobile surveys.
EPT human viewing passed on a 110-billion-point repository through requested
hierarchy/nodes only. A dedicated localized terrestrial scan and weaker physical
hardware remain untested. See the [stability evidence](PHASE_34A3_3_STABILITY_EVIDENCE.md)
for exact release gates, and the [stability contract](../development/POINT_CLOUD_VIEWER_STABILITY_CONTRACT.md)
for authority and ownership requirements.
