# Phase 31H Polygon Launch Regression

## Contract

With the Processing Engine READY and a valid Polygon request, Process obtains a product-scoped token from the shared service before `_begin_logical_job()`. The execution service consumes the same state/token and launches the durable coordinator with managed Python. No legacy backend status or local QGIS import can reinterpret readiness.

If the fingerprint changes, the shared state becomes repair required and no logical job/coordinator directory is created. Current LiDAR, polygon, products, and output selections remain intact; the Process page displays **Repair Processing Engine**.

## Evidence

Static launch tests verify shared-service/token use and explicit managed adapters. Runtime tests verify token identity and stale-handler rejection. The final managed Windows contract probe verifies the package runtime. A fresh live QGIS run is still required to record coordinator PID and CHM/Rumple outputs.
